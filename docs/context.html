주의할 점

현재 adapter 내부 capability 이름은 최종 MCP tool 이름을 확정한 것이 아니다. 실제 tool naming은 기존 Membase MCP 호환성과 migration parity를 확인한 뒤 확정한다.

왜 하는가

기존 Claude, Cursor, Hermes, OpenClaw connector repo가 client별로 흩어져 있고 구조도 서로 다르다. 이 레포는 공통 설치, auth, MCP config, adapter boundary를 한 곳에 두어 유지보수 비용을 낮추고, marketplace와 deprecation 계획을 일관되게 만들기 위한 통합 target이다.

Architecture Decision

Connectors expose stable capabilities and install/config artifacts. Membase internal implementation details stay behind the product API. Shared behavior belongs in packages/core and packages/connector-sdk. Client-specific behavior belongs in clients/*.

Canonical decision file: ADR 0001.

Open Questions

  • Final MCP tool names are not locked by the adapter capability names.
  • OpenClaw native artifacts are snapshot-guarded; runtime hooks and tools still need parity implementation after an explicit migration decision.
  • Hermes provider import/register behavior and native artifact evidence are guarded; live API behavior still needs a migration decision.
  • Cursor HTTP MCP compatibility is now the primary path to preserve, not a generic fallback.
  • Claude plugin-local MCP compatibility and native artifact evidence are now guarded; commands/hooks/skills still need an explicit migration decision before any behavior is ported.
  • Live MCP smoke tests still need Hermes live API behavior, OpenClaw hook/tool behavior, and test credentials rather than one forced generic package.
  • pnpm smoke:live:preflight now guards the blocked live-smoke state until D2/D3 are implemented.
  • @membase/mcp-server currently returned 404 from public npm lookup, so it remains only a Hermes/OpenClaw placeholder unless separately accepted.
  • Claude plugin/native snapshots, Cursor transport/native snapshot, Hermes provider/native snapshot, and OpenClaw native snapshot/entrypoint parity have local checks; Claude native behavior, Cursor rules/skills/assets copy, Hermes live behavior, and OpenClaw hook/tool copy are still pending.
  • Client-native parity tests still need implementation after runtime migration decisions.
  • Remaining launch decisions are centralized in docs/runtime-parity-decisions.md.
